## 5. מודל מוצע — Bundle ו־BundleItem (תכנון חדש)

עיקרון: **מארז הוא מוצר.** `Bundle` הוא הרחבה 1:1 של `Product`. `BundleItem` מפנה למוצרים קיימים לפי `ProductId` ואינו מעתיק אותם.

```sql
-- מארז = מוצר עם סוג 'bundle'. אין טבלת מוצרים נפרדת למארזים.
CREATE TABLE Bundle (
  ProductId          INT PRIMARY KEY REFERENCES Product(ProductId),  -- 8254
  BundleKind         VARCHAR(20) NOT NULL
                     CHECK (BundleKind IN ('physical','digital','physical_plus_digital')),
  PricingMode        VARCHAR(20) NOT NULL DEFAULT 'fixed'
                     CHECK (PricingMode IN ('fixed','sum_of_items','discount_pct')),
  StockMode          VARCHAR(20) NOT NULL DEFAULT 'own'
                     CHECK (StockMode IN ('own','min_of_items','unlimited')),
  OnComponentHidden  VARCHAR(20) NOT NULL DEFAULT 'keep_selling'
                     CHECK (OnComponentHidden IN ('keep_selling','hide_bundle','block_checkout')),
  LegacyRelationScreenId INT NULL,     -- מזהה מסך הקשרים ב־UPME (אחד מ־59)
  Notes              NVARCHAR(MAX) NULL
);

CREATE TABLE BundleItem (
  BundleItemId       INT IDENTITY PRIMARY KEY,
  BundleProductId    INT NOT NULL REFERENCES Bundle(ProductId),
  ComponentProductId INT NOT NULL REFERENCES Product(ProductId),  -- הפניה, לא עותק
  Quantity           INT NOT NULL DEFAULT 1 CHECK (Quantity > 0),
  SortOrder          INT NOT NULL DEFAULT 0,
  IncludesDownload   BIT NOT NULL DEFAULT 1,  -- האם הרכיב מעניק זכות הורדה
  LegacyRowId        INT NULL,                 -- אחת מ־347 שורות הרכיב
  CONSTRAINT UQ_BundleItem UNIQUE (BundleProductId, ComponentProductId),
  CONSTRAINT CK_BundleItem_NoSelf CHECK (BundleProductId <> ComponentProductId)
);
CREATE INDEX IX_BundleItem_Component ON BundleItem(ComponentProductId);  -- "באילו מארזים מופיע רכיב X"
```

כללי התנהגות מוצעים (לאשר מול המערכת הישנה):

1. **שינוי רכיב משותף** (שם, תמונה, קובץ) משתקף מיד בכל המארזים, כי זו הפניה.
2. **מחיקת רכיב**: מחיקה רכה בלבד (`Product.DeletedAt`). `BundleItem` נשאר, והתנהגות המארז נקבעת לפי `OnComponentHidden`. מחיקה קשה של מוצר שמשמש רכיב תיחסם ב־FK.
3. **מחיר היסטורי**: בהזמנה נשמרת שורת מארז עם המחיר ששולם. רכיבים נשמרים בטבלת `OrderItemComponent` בנפרד, עם הקצאת מחיר אופציונלית לצורכי החזרים. ראה 09.
4. **הורדות**: ברכישת מארז דיגיטלי נוצר `DownloadGrant` לכל `BundleItem` עם `IncludesDownload=1`, או לנכס המאוחד של המארז אם כך עובדת המערכת הישנה.
5. **מלאי**: אם `StockMode='min_of_items'`, הזמינות = min(מלאי רכיב ÷ כמות). אחרת מלאי עצמאי.

## 6. בדיקות קבלה למארזים (תקציר — המלא ב־15)

- ספירת `BundleItem` אחרי ייבוא = 347, ספירת `ComponentProductId` שונים = 305, ספירת `Bundle` עם רכיבים = 59. **רק אחרי שהמספרים יאומתו בניהול.**
- למארז 8254: רשימת הרכיבים בסדר זהה למסך הקשרים ב־UPME, וכל רכיב מפנה ל־ProductId קיים.
- אף `BundleItem` אינו יוצר שורת `Product` חדשה (מספר המוצרים לפני ואחרי ייבוא המארזים זהה).
