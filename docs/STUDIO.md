# GREENTEC AI Film Studio – מדריך הפעלה ומפרט מימוש

המודול מממש את "מפרט אנשי הצוות הווירטואליים" בתוך ממשק הניהול: **אולפן AI → פרויקטי סרטים / צוות האולפן**.

## מה בנוי

| נושא במפרט | איפה במערכת |
|---|---|
| 14 אנשי הצוות (AI-01 עד AI-14): תפקיד, כישורים, אחריות, תוצרים, מבחן כשירות | `lib/studio/agents.ts`; מסך "צוות האולפן" וכרטיס לכל סוכן |
| התמחות אמיתית: מתודולוגיה ונהלים | לכל סוכן יש שיטת עבודה בשלבים ורשימת בדיקה עצמית. שתיהן נכנסות להנחיות המערכת בכל הרצה |
| זיכרון הפקה במסד נתונים ולא בשיחה | כשמשימה עוברת ל"מוכנה", המערכת נועלת את הגרסאות המאושרות (`approvedVersions`). הסוכן מקבל רק אותן, את הסיפור ואת חוזה המשימה |
| תוצרים מובנים | כל הרצה מחזירה JSON לפי סכמה קבועה. כל תוצר נשמר כגרסה חדשה של נכס |
| ביקורת עצמית | מעבר ל"בבדיקה" אפשרי רק אם יש תוצר שמור לכל תוצר מחייב, וגם ביקורת עצמית |
| תיקון ממוקד | בסבב תיקון הסוכן מקבל את הערות התיקון ואת הגרסה שנדחתה, עם הוראה לשנות רק את מה שנדרש |
| דיווח אמיתי | כל הרצה נרשמת ביומן עם המודל שענה בפועל, הטוקנים והעלות. הבודק מחויב לפרט מה **לא** בדק |
| אישורים והרשאות | אין שליחה ל־Claude בלי אישור המפיק לפרויקט. מנוע חיצוני חייב להופיע ברשימת המנועים המאושרים. אישור ההפצה נעשה רק בידי אדם |
| חוזה העבודה (§6) | כל 14 השדות נמצאים במשימה: Task ID, Project ID, Scene/Shot, סוכן מבצע, קלטים, גרסאות מאושרות, Brief, דרישות טכניות, מגבלות, תקציב, תוצרים, תנאי אישור, סוכן בודק ומצב |
| מצבי משימה | DRAFT → READY → RUNNING → REVIEW → APPROVED · REVIEW → REVISION_REQUIRED → RUNNING · BLOCKED → HUMAN_DECISION (`lib/studio/workflow.ts`) |
| גרסה מאושרת לא מוחלפת | `FilmAssetVersion` אינה ניתנת לשינוי. כל שינוי יוצר גרסה חדשה |
| תהליך 6 השלבים (§5) | 19 משימות עם תלויות, בודקים ותקציב לכל משימה (`PLAN` ב־`workflow.ts`) |
| דוגמת העששית (§7) | זה בדיוק המסלול: תסריט → בימוי → דמויות/חדר → סטוריבורד → אנימציה → וידאו → רציפות → סאונד → עריכה → איכות |
| מבחן הקבלה (§8) | לשונית "מבחן קבלה" בכל פרויקט: ציון 1–5 ל־10 תחומים. נדרש 4 לפחות בנאמנות לדמויות, בתנועה, בהבנת הסיפור ובעריכה, וללא תקלת תוכן קריטית |
| מבחני כשירות לכל סוכן | בכרטיס הסוכן: "פתיחת פרויקט מבחן כשירות" (פרויקט מבחן עם משימה אחת ותקציב של $5) |
| תפעול וזכויות (AI-14) | לשוניות "תקציב" ו"זכויות". אישור ההפצה נחסם אם חסרות זכויות מאומתות לשימוש מסחרי, או אם יש חריגה מהתקציב |

## מה עושה AI ומה לא

- **Claude API** מבצע את עבודת הטקסט והתכנון: תסריט, הוראות בימוי, תוכנית הפקה, ספרי דמויות ועולמות (כטקסט), Shot List, Voice Bible ומילון הגייה, Cue Sheet, תוכנית אנימציה, חבילות פרומפט למנועי וידאו, EDL, דוחות רציפות, איכות ותפעול, וגם הבדיקות של הסוכנים הבודקים.
- **מדיה** (תמונות, וידאו, קול ומוזיקה) **לא נוצרת בשרת**. הסוכן מכין לכל פריט פרומפט מלא (`*__requests`). את הקובץ מפיקים במנוע שהמפיק אישר (Kling, Seedance, Veo, Runway, LTX, ElevenLabs ועוד) ומעלים אותו במסך המשימה. הקובץ עולה ישירות לדלי, תחת `studio/{project}/`, יחד עם המנוע, ההגדרות והעלות.
- **בודק AI לא רואה וידאו ולא שומע שמע.** במשימה עם תוצרי מדיה הבודק נותן המלצה בלבד, והמפיק מאשר אחרי צפייה.
- חיבור ישיר ל־API של מנועי הווידאו והקול (תורים, ניסיונות חוזרים) הוא השלב הבא. הוא דורש בחירת ספקים, מפתחות ותקציב, באישורך.

## הפעלה

1. ב־Railway מוסיפים את המשתנה `ANTHROPIC_API_KEY`. אופציונלי: `STUDIO_MODEL`, כברירת מחדל `claude-opus-5-5`.
2. אולפן AI → פרויקטי סרטים → פרויקט חדש: שם, תקציב בדולרים והסיפור המלא.
3. בלשונית "הגדרות ואישורים": מסמנים אישור לשימוש ב־Claude API לפרויקט ורושמים את המנועים החיצוניים המאושרים.
4. "יצירת משימות ההפקה" פותחת 19 משימות. משימה מתחילה כ"טיוטה": בודקים את החוזה, מעבירים ל"מוכנה לביצוע" ולוחצים "הפעלת הסוכן".
5. בסיום, משימה רגילה עוברת ל"בבדיקה". במשימת מדיה מעלים קודם את הקבצים ורק אז מעבירים ל"בבדיקה". אחר כך לוחצים "בדיקה ע״י AI-xx", או מאשרים או מחזירים לתיקון בעצמכם.
6. "ממתין להחלטתך" מרכז כל משימה חסומה, כל שאלה של סוכן וכל בדיקה ששמורה למפיק.

## תקציב

- לכל משימה יש תקרה, כחלק קבוע מתקציב הפרויקט. אפשר לשנות אותה בחוזה.
- לפני כל קריאה המערכת מחשבת את העלות המקסימלית האפשרית לפי המחיר היקר ביותר בשרשרת, וקובעת לפיה את `max_tokens`. לכן קריאה לא יכולה לעבור את מה שנשאר. אם לא נשאר מספיק תקציב, ההרצה נחסמת.
- העלות בפועל נרשמת לפי המודל שענה (`response.model`) והטוקנים שנצרכו. עלויות של מנועים חיצוניים נרשמות בזמן ההעלאה, או בלשונית "תקציב".
- כשהמודל מסרב לבקשה, `fallbacks: "default"` מריץ אותה במודל חלופי מתאים. המודל שענה מופיע בגרסה וביומן.

## מגבלות ידועות

- הרצה רצה ברקע בתוך שרת ה־web. אם השרת מתאתחל באמצע הרצה, יופיע הכפתור "שחרור הרצה תקועה" והמשימה תעבור להחלטתך. לא נשמר תוצר חלקי.
- הבדיקה המקומית נעשתה מול שרת דמה שמחקה את ה־API. ההרצה הראשונה מול Claude האמיתי תהיה על staging, אחרי שתוסיף מפתח.
